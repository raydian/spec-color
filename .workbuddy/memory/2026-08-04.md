- 任务：为 384 个传统色（24 节气分组，顶层为数组的数组）每个色块新增 `description`（诗意介绍）与 `usage`（使用场景）两字段。
- 方法：写 `enrich_colors.py`（Python）对每色按 RGB→HLS 计算色相/饱和/明度，归入 12 个传统色家族（素白/淡灰/灰褐/墨/朱红/橙黄/明黄/青绿/碧青/青蓝/黛紫/红紫）；诗意文案锚定原 `sentence`+`author`+`sentenceFrom`，并叠加节气意象与明度气质；场景文案按家族给出。色名哈希选样多套变体以保证多样性。
- 关键修正：低饱和度的红/绿灰曾被误判为「朱红」（色相角落在 0/360° 附近不可靠），改为「中性色阈值 S<15；红相需 S≥30、橙相需 S≥26」才归入彩度家族，低饱和回落到灰褐/淡灰。
- 结果：384 条全部含新字段，原字段顺序保留。脚本可复跑（确定性）。文件增大到 5084 行。
- 注意：原数据存在 hex 与 rgb 不一致（如多处 hex 误填 #CC5D20），description 以 rgb 为准（与渲染通道一致）。如需以 hex 为准需先修源数据。

## 新增 pairings 搭配色数组字段
- 为每个色块新增 `pairings`：数组，3-5 项，每项含 `name`/`hex`/`relation`/`method`/`usage`。
- 算法（在 enrich_colors.py 的 build_pairings）：彩度色按 同色系深浅(L差≥18的同家族) → 邻近色(H+30, 色相差8-55) → 互补色(H+180) → 三角色(H+120) → 中性平衡(按明度反差选 墨/灰褐 或 素白/淡灰) 选真实色板内的色；中性色(素白/淡灰/灰褐/墨)改走 暖调(H40)+冷调(H210)+对比中性。best_near 按色相差+明度差+饱和惩罚打分取最优。
- 结果：384 条全部 3-5 项（77 条=3，307 条=5），无条目内重名。互补/三角的色相验证接近 180°/120°。
- 校验发现原数据 hex/rgb 不一致会影响 partner 展示 hex（逻辑以 rgb 为准，属已知限制）。
